## Фаза 1. Страховочная сетка: линт, CI, базовые тесты

Цель — чтобы сломанный код не доходил до `master` и до сайта незамеченным. Сейчас единственная проверка — сама сборка внутри деплоя.

1. **Довести линт до нуля.**
   - Механика: `oxlint --fix` — `prefer-node-protocol` (5), `no-useless-spread`, `no-useless-undefined`.
   - Неиспользуемый код (`no-unused-vars`, 4): `families/page.tsx` (`fetchTransactions`), `lib/seo/schema.ts`, `lib/data/transactions.ts`; пустой `components/shared/icons/index.tsx`.
   - `react/set-state-in-effect` (3): `auth-provider.tsx`, `hooks/use-mobile.ts`, `components/ui/carousel.tsx` — переписать без синхронного `setState` в эффекте (для `isMounted` — `useSyncExternalStore` или убрать флаг).
   - `react/purity` и `button-has-type` в `components/ui/sidebar.tsx`; `prefer-tag-over-role` в `breadcrumb.tsx` и `item.tsx` — это вендорные shadcn-компоненты: либо поправить, либо добавить в override рядом с `carousel.tsx`.
   - Предупреждения: `require-await` (13, в основном `lib/api/*` — см. фазу 2), `no-explicit-any` (6), `consistent-type-definitions` (6), `no-console` в скриптах (для `scripts/**` правило можно отключить override'ом).
   → проверка: `bun run lint` — 0 ошибок.
2. **Добавить скрипты** `typecheck` (`tsc --noEmit`) и `format:check` (`oxfmt --check`) в `package.json`.
3. **CI-проверки до деплоя**: отдельный job (на pull request и push) — `lint`, `format:check`, `typecheck`, `test`. Деплой зависит от него (`needs`).
4. **Починить workflow деплоя** (`.github/workflows/deploy.yml`, `.github/actions/setup-bun/action.yml`):
   - ключи кэша считаются от `bun.lockb`, а лок-файл — `bun.lock` → `hashFiles` даёт пустую строку, кэш фактически никогда не инвалидируется;
   - `bun-version: "latest"` → зафиксировать версию, чтобы сборка не ломалась от обновления Bun;
   - в CI вызывается `bun next build`, а не `bun run build`, поэтому `scripts/build-data.ts` не запускается и `DATA_ENCRYPTION_KEY` пишется в `.env.production` впустую (см. «Открытые вопросы» №1).
5. **Подключить тест-раннер** (см. «Открытые вопросы» №3). Первые тесты — там, где ошибка стоит денег:
   - балансы: `FamilyTransactionsRepository.calculateBalance / calculateAllBalances`;
   - хелперы распределения сумм в `lib/data/transactions.ts` (`cnst`, `fade`, `line`, `none`, `english`, `music`…);
   - инвариант данных: сумма долей семей в каждой транзакции равна `value` транзакции (с учётом округления `Math.floor`);
   - все `teacher` / `family` / `target.user` id в транзакциях существуют в `users` / `families`.
   → проверка: тесты зелёные в CI; намеренно сломанная сумма в транзакции роняет тест.

## Фаза 5. Безопасность и приватность данных

Самый важный по смыслу, но и самый объёмный блок — поэтому после того, как есть тесты и порядок в данных.

**Проблема.** Сайт статический, и весь бандл публичен. Любой, кто откроет DevTools, видит без логина: телефоны (9) и даты рождения (45) из `users.ts`, включая детей, все транзакции и суммы. Пароли семей лежат в бандле как **несолёный SHA-256** — при минимальной длине 6 символов они перебираются офлайн за минуты. Логин защищает только интерфейс, не данные.

Варианты (по возрастанию сложности):

1. **Минимум:** убрать из бандла то, что не нужно для работы (телефоны, точные даты рождения), и усилить пароли (длиннее, случайные).
2. **Шифровать данные на клиенте ключом из пароля** — совместимо с GitHub Pages. На сборке данные каждой семьи (или общие данные) шифруются ключом, выведенным из пароля через PBKDF2/Argon2 с солью; в браузере расшифровываются после ввода пароля. Без пароля в бандле только шифротекст. Требует переработки потока данных: страницы перестают рендерить данные на сборке и получают их на клиенте после логина.
3. **Хостинг с контролем доступа** (например, Cloudflare Pages + Access) — защита на уровне сервера без своего бэкенда. Противоречит решению «только GitHub Pages» в `.agent/PROJECT_CONTEXT.md`, поэтому только как осознанный выбор.

> Серверная проверка через Next.js middleware при `output: 'export'` невозможна — middleware в статическом экспорте не выполняется.

**Проверка:** в собранном `out/` поиск по номеру телефона и имени ребёнка ничего не находит (`grep -r` по `out/`).
