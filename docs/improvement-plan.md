## Фаза 5. Безопасность и приватность данных

Самый важный по смыслу, но и самый объёмный блок — поэтому после того, как есть тесты и порядок в данных.

**Проблема.** Сайт статический, и весь бандл публичен. Любой, кто откроет DevTools, видит без логина: телефоны (9) и даты рождения (45) из `users.ts`, включая детей, все транзакции и суммы. Пароли семей лежат в бандле как **несолёный SHA-256** — при минимальной длине 6 символов они перебираются офлайн за минуты. Логин сейчас защищает только интерфейс, не данные.

Варианты (по возрастанию сложности):

1. **Минимум:** убрать из бандла то, что не нужно для работы (телефоны, точные даты рождения), и усилить пароли (длиннее, случайные).
2. **Шифровать данные на клиенте ключом из пароля** — совместимо с GitHub Pages. На сборке данные каждой семьи (или общие данные) шифруются ключом, выведенным из пароля через PBKDF2/Argon2 с солью; в браузере расшифровываются после ввода пароля. Без пароля в бандле только шифротекст. Требует переработки потока данных: страницы перестают рендерить данные на сборке и получают их на клиенте после логина.
3. **Хостинг с контролем доступа** (например, Cloudflare Pages + Access) — защита на уровне сервера без своего бэкенда. Противоречит текущему решению «только GitHub Pages» в `.agent/PROJECT_CONTEXT.md`, поэтому только как осознанный выбор.

> Пункт 17 из `PLAN.md` («Auth Middleware + серверная проверка») при `output: 'export'` невозможен — middleware в статическом экспорте не выполняется. Его заменяет этот блок.

**Проверка:** в собранном `out/` поиск по номеру телефона и имени ребёнка ничего не находит (`grep -r` по `out/`).
